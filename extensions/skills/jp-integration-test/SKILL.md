# jp-integration-test

日本企業ソフトウェア開発の結合試験（Integration Test）スキル。
単体試験で個別検証した部品間の連携（モジュール間・サービス間・API層・DB含む）を検証する。

## Purpose

単体テストで個々の部品が正しく動くことを確認済みとした上で、それらの部品が**組み合わさった時**に
正しく連携するかを検証する。日本の V-model では単体試験 → 結合試験 と段階が分離される。

## Input

- 実装コード（各モジュール／サービス）
- 単体テスト結果（どの UT が通ったか）
- 基本設計書／詳細設計書（モジュール間のインターフェース仕様）
- 要件（REQ-xxx）

## Output

各結合テストケース：

| フィールド | 説明 |
|---|---|
| ID | IT-001（連番） |
| Requirement | 由来要件（REQ-xxx） |
| Precondition | 前提条件 |
| Input | 入力値 |
| Steps | 手順 |
| Expected | 期待結果（モジュール連携の結果） |

## 結合試験の重点

- **API 層 → Service 層 → Repository/DB** の一連の流れを1ケースで検証
- モジュールAの出力がモジュールBの入力になる境界を明示
- 単体試験で担保済みの範囲は重複せず、**結合の成否**に集中
- 可能なら実際にテスト実行（JUnit integration test / SpringBootTest など）
